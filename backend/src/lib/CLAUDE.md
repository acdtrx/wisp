# Backend Ops Rules (storage, cloudInit, paths)

- **paths.js:** Wisp app-glue path helpers and the **API-input security gate** for VM file paths. Exports: `getVMBasePath(name)`, `getImagePath()`, `ensureImageDir()`, `resolveLibraryPath(p)` (relative→absolute via image library), `assertPathInsideAllowedRoots(absPath, vmName)` (rejects paths outside `imagePath` and per-VM dir) and its predicate `isPathInsideAllowedRoots` (passed to `vmManager.restoreBackup` as the CD-ROM source policy). **Routes resolve+validate user-supplied paths here, before passing absolute paths to vmManager.** vmManager itself is policy-agnostic about which host paths a deployment considers "allowed."
- **Strict managers** (the rule lives in `docs/CODING-RULES.md` §7: zero Wisp-glue imports; manager changes only for generic libvirt/containerd functionality). Mechanics here: each manager owns its private error factory (`vmError` / `containerError`, inlined in `vmManagerShared.js` / `containerManagerConnection.js`), its private validators (`vmManagerValidation.js` / `containerValidation.js`), and its private path helpers / atomic-write copy. Generic ISO ops (`attachISO` / `ejectISO`) carry `{ createIfMissing }` / `{ removeSlot }` opts so cloud-init's special slot handling rides the public primitive — the orchestration lives in `lib/cloudInit.js` (Wisp glue), not in vmManager.

- **Manager network events (push, not pull):**
  - `vmManager.subscribeVMNetworkChange(handler)` — `(name, snapshot)` where `snapshot = { stateCode, ip, hostname }` when running, `null` when stopped. Linux impl wires DomainEvent + AgentEvent + a 60s safety probe internally (`vmManager/linux/vmManagerNetwork.js`), diffs against last-emitted state, fires on change.
  - `containerManager.subscribeContainerNetworkChange(handler)` — `(name, snapshot)` where `snapshot = { state, ip, ip6 }` when running on a bridge (`ip6` = kernel-SLAAC global IPv6 from `/proc/<taskPid>/net/if_inet6`, null on v4-only LANs), `null` when stopped/removed. Linux impl is `containerManager/linux/containerManagerNetworkEvents.js`. Subscribes to `subscribeContainerListChange` (event-driven on every containerd lifecycle event) plus a 60s timer to catch DHCP renewals and SLAAC changes inside the netns. **Persists new addresses into `container.json` before firing** — containerManager owns the durable record, glue (`lib/containerMdnsReconciler.js`) reacts only to the event.
  - `containerManager.subscribeContainerNetnsRemoved(handler)` — `(name)` after Wisp deleted a container's netns (and with it the host-side veth): stale netns cleared at start, `teardownNetwork`, rename orphan cleanup. Not on stop (stop keeps the netns). No replay. Glue (`containerMdnsReconciler`) reacts with `republishProbingGroups()` — avahi 0.8 strands entry groups probing on a removed interface. Darwin: never fires.
  - Both network-change events: replay-on-subscribe (a new handler gets one fire per current snapshot before subscribe returns), so glue starting after the manager has already populated state still catches up to running workloads. Darwin: never fires.
  - All A-record register/deregister calls live in the reconcilers (`lib/{vm,container}MdnsReconciler.js`). Managers carry **zero** `registerAddress`/`deregisterAddress` calls. SRV/TXT services on the container side stay in containerManager (still tied to the per-container `services` array) — that cleanup is a separate future step.
- **Manager configure() (push model):** `lib/managerBootstrap.js` (`configureManagers` / `connectManagers` / `disconnectManagers`, shared by `backend/src/index.js` and the migration runner `backend/scripts/migrate.mjs`) calls `vmManager.configure({ vmsPath })` and `containerManager.configure({ containersPath, resolveMount, tryAcquireOperationLock })`; `index.js` runs it before any route registers. `connect(…, { watchEvents: false })` (both managers; the runner's mode) skips the event subscriptions — DomainEvent listener + QEMU-binary watcher, containerd events stream (and with it the restart policy) — makes the network reconcilers inert and bypasses the list caches; the backend always connects with the default `true`. The `resolveMount` callback is a sync `(id) => null | { id, mountPath, label? }` over `getConfigSync().mounts`; `tryAcquireOperationLock` is the sync `(name, operation) => release | null` of `lib/containerOperationLock.js`, held by the manager's own restart-policy and autostart starts (slot: `containerManager/linux/containerOperationGuard.js`). Internal helpers: `lib/vmManager/linux/vmManagerPaths.js` (vmManager-private, holds `getVMBasePath`/`getVmsPath` only — image-library policy stays in Wisp glue); `lib/containerManager/linux/containerPaths.js` (containerManager-private, holds path getters + `resolveMount` slot); `lib/containerManager/linux/atomicJson.js` (vendored copy of `lib/atomicJson.js`, kept private to break the policy edge ahead of eventual lib extraction). The `oci-image-meta.json` sidecar lives at `<containersPath>/.oci-image-meta.json` (containerManager-owned cache).
- **Streaming route teardown (sse.js, WS routes):** a response/WebSocket `'close'` event fires once, so a listener attached after an `await` (or after the async auth hook, for which the client may already be gone) never runs. SSE handlers register every teardown — timers, subscriptions, job-stream registrations, log tails — through `onSSEClose(reply, fn)`, which runs `fn` immediately when the response is already destroyed; never `request.raw.on('close')`. WS handlers re-check `socket.readyState !== socket.OPEN` after their setup `await` and tear down what that await produced (TCP leg, exec session) before returning.
- **Disk copy + resize (storage/diskOps.js, exposed via `storage/index.js`):** every qemu-img call passes `-f <format>` (never probed); a library/user image's format comes from `imageFormatForFile` and is checked with `inspectDiskImage` (no backing file / data file, qcow2 or raw) before convert/attach/resize — see `docs/spec/VM-MANAGEMENT.md` § Untrusted images. `qemu-img convert -f <fmt> -O qcow2 <src> <dst>` then `qemu-img resize -f qcow2 <dst> <size>G` if needed. Destination is the per-VM directory. Progress via child process stdout with `-p` flag; stream to client via SSE. Source file never modified or moved.
- **Cloud-init (cloudInit.js):** Wisp-glue orchestrator — owns ISO build (cloud-localds / genisoimage), config persistence, and attach/detach via `vmManager.attachISO(name, 'sde', isoPath, { createIfMissing: true })` and `vmManager.ejectISO(name, 'sde', { removeSlot: true })`. Password hashed via `openssl passwd -6` (child process). Stored under per-VM directory (`getVMBasePath`). GitHub key fetch is server-side only; frontend never calls github.com. **Routes drive the create-time flow:** `routes/vms.js` POST first checks the name is free (`vmManager.assertVMNameAvailable` — libvirt + on-disk dir), then passes `generateCloudInit(name, spec.cloudInit)` to `vmManager.createVM` as its `populateVMDir` callback, which runs inside the freshly (exclusively) created VM dir; createVM's rollback removes that dir on any failure, so the route has no cloud-init cleanup of its own. **Restore rebuilds the ISO the same way:** backups hold `cloud-init.json` but not the ISO, and `routes/backups.js` passes `rebuildCloudInitISO(name, vmDir, xml)` as the `populateVMDir` hook of `restoreBackup` (run after the payload lands, before define). vmManager itself never imports cloudInit.js.

# vmManager Rules

These rules apply to `vmManager/index.js`, `vmManager/vmManagerShared.js`, and files under `vmManager/linux/` and `vmManager/darwin/`.

- **Only DBus/libvirt caller:** No route or other module imports `dbus-next` for libvirt or calls libvirt except through `vmManager`. Linux libvirt logic lives under `vmManager/linux/`; the `vmManager/index.js` facade re-exports the platform implementation. (Avahi uses `dbus-next` in `lib/mdns/linux/avahi.js` only.)
- **Domain object paths:** `/org/libvirt/domains/<uuid>`. UUIDs from ListDomains. Use `getDomainObjAndIface(path)` — it caches the proxy in `connectionState.domainProxyCache` and skips the per-call DBus Introspect. Cache is cleared on bus disconnect and on `VIR_DOMAIN_EVENT_UNDEFINED`. Do not stash proxy references elsewhere; do not cache across reconnects.
- **VNC port:** Call `org.libvirt.Domain.GetXMLDesc(0)`, parse `<graphics type='vnc' port='...'>` from the XML. Expose via a function used by the console route; the route bridges TCP (`node:net` createConnection) to WebSocket. No third-party TCP proxy.
- **UEFI firmware:** Scan known firmware paths at startup; expose via GET /api/host/firmware. Paths vary by distro (e.g. Ubuntu /usr/share/OVMF, Fedora /usr/share/edk2/ovmf).
- **Dual CDROM:** Every VM XML defines sdc and sdd at creation, even if empty. Empty CDROM: no `<source>`. Attach/eject via `org.libvirt.Domain.UpdateDevice(xmlString, flags)` with `flags = 3` (LIVE + CONFIG).
- **CPU topology:** Always full topology in domain XML. Never `<vcpu>N</vcpu>` alone. Emit `<vcpu placement='static'>N</vcpu>` and `<cpu mode='host-passthrough' check='none' migratable='on'><topology sockets='1' dies='1' cores='N' threads='1'/></cpu>`. Same at VM creation and in updateVMConfig.
- **Live vs offline:** anything passed to `DomainDefineXML` for an existing domain is built from the **inactive** XML (`getDomainXML(path, { inactive: true })`) — the live XML of a running VM lacks pending-restart edits, and defining from it reverts them. Live XML is for runtime reads (VNC port, stats) and for device elements sent to `UpdateDevice` / `AttachDevice` with the LIVE flag. Device hot-plug uses `flags = 3` (LIVE + CONFIG), config-only `flags = 2`. updateVMConfig only redefines; on a running VM it returns `{ requiresRestart: true }` and sets the persisted `wisp:pendingRestart` flag (`since = now`) when the definition (minus `<metadata>`) changed — `domainDefinitionSignature` before vs after. The flag holds the save time (`since`); the list refresh and `getVMConfig` drop it once the QEMU process started later (`vmManagerPendingRestart.js`, start time from `/proc` via `vmManagerProc.js`); `setVMPendingRestart` sets it from outside. Metadata writers (`setWispMetadata`, `setWispPendingRestart`) mutate their own children of the existing `wisp:prefs` element, never rebuild it.
